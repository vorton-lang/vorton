# Unwind 与全体重新开始

本文件属于 [task-pipeline](../SKILL.md)，只在主 skill 的恢复机会耗尽，或用户明确要求终止当前尝试时执行。它终止整个实现尝试，不是再一次返修。用户已批准的该规则授权按下述边界清理失败尝试并创建 fresh 主会话；不授权删除无关工作、改写已合并历史或改变合同。

## 停止与唯一可传递内容

- 立即停止该尝试全部 agent 的设计、实现与验证，以及相应后台写入。旧主会话只完成本文件规定的清理与交接。将主 Planning、Readiness、Execution、Verification 及参与评估的所有会话都视为已受旧路线影响，均不得继续充当新尝试的角色；禁止只换实现 agent、fork 旧会话或以摘要恢复旧主会话。
- 清理前只整理一份简短交接：执行的经验教训、仍未决的问题、实际遇到且没有解决的困难。分别写清已观察到什么、仍不知道什么；不把猜测写成根因，不把未解决写成已解决。
- 交接不得含具体实现、代码或伪代码、补丁、算法或数据结构方案、内部符号与模块设计、测试/探针源码、旧候选 SHA/分支/PR/会话标识或指向执行记录的链接，也不得夹带“保留哪些机制”“按此方案重做”等实现建议。可以描述合同层面的预期行为与实际障碍，但不能借经验教训复述旧实现。
- 新主会话只接收上述交接、用于独立定位 authority 的 repository、Milestone、Issue 稳定标识，以及“unwind 后的新尝试”这一工作模式。模式是读取边界的流程指令，不是旧尝试的内容；后续每个 fresh 角色输入都必须明确携带该模式。当前合同与规范由新角色重新读取，不传旧正文快照、设计评审结论、验收结论、失败日志或阶段 prompt。

## 清理失败尝试

- 先列明本次尝试独占的 PR、remote/local branch、worktree、临时副本、构建产物、探针、日志、报告及会话载荷，核对唯一 writer 已停止、目标确属本次尝试且没有待保护的用户或其它任务内容。只保留上面的交接；无法确定归属的内容不得猜测删除。
- 关闭未合并 PR，清理本次失败实现的 remote/local branch、worktree、临时实现、执行记录和可删除的阶段评论/会话载荷。本地批量或递归目录清理由用户手动执行：Planning 先交付逐项核对的绝对路径清单和可审阅命令或脚本，等待用户操作后只读复核；不自动尝试、改换工具重试或反复索要同一批准。不要留失败实现的备份、patch、隐藏目录或备用分支供新尝试恢复。共享缓存、其它任务、用户文件、已合并的 main 和当前 Milestone/Issue 合同不属于清理对象。
- 清理使用平台支持的工具。准备递归删除或移动命令前必须核对 resolved absolute path 位于逐项确认的目标范围；不用仓库范围的强制清扫，也不以历史重写、垃圾回收、直接编辑应用数据库等手段强求彻底擦除。工具拒绝时只报告实际返回的限制，不猜测原因或声称再次批准必能解除。已合并内容不走本清理流程，若确需撤销须报告具体影响并由用户另行决定。
- 工具或平台不能删除的 PR 历史、Git 对象或会话，应关闭、归档或隔离，并向用户如实报告残留和限制；不得声称已物理抹除。新尝试禁止检索、读取、导入或恢复这些残留。无法停止旧 writer、无法排除失败实现进入新 checkout，或交接仍夹带旧实现时，不得启动新实现。
- 清理范围或实际不可恢复操作缺少授权时，先完成可审阅的目标清单，再仅就缺失部分向用户说明并取得批准；已明确授权且归属核对无误的操作不重复询问。

## 重开与合同复审

- 使用真正 fresh 的新主会话，从干净的当前 remote default branch 开始，不 fork、不继承聊天历史、调用者 working tree 或旧 candidate。启动全部新 agent 时仍显式 `fork_turns: "none"`，不得恢复旧 agent。若宿主不能创建不继承历史的新主会话，交付允许的交接并请用户新开；旧主会话不能自行冒充已清空上下文。
- 新主会话先重新读取仓库 authority、当前 Milestone 与 Issue 正文及其原生编辑历史，重新审视合同中的目标、边界、依赖与验收，结合交接中的困难识别尚未解决的问题。不能采用旧 Readiness 的 `CLEAR` 或旧架构结论；不得通过 Issue 关联记录、旧 PR 或 Git 历史把已排除的失败实现重新引入。
- 在“unwind 后的新尝试”模式中，Readiness 只查询 open PR 的最小关联元信息以确认当前 active 状态，不读取 closed 关联 PR、旧阶段报告或其 diff；repository authority 从当前 remote default-branch object 读取，不探索其它历史实现。新 Execution/Verification 只读取本次新建 PR、该阶段 exact SHA 和所需比较基线。此边界优先于普通流程的关联 PR 与历史读取规则，不需要也不允许传递旧 PR/commit 黑名单。
- 合同不变且无重大未决时，按正常 `Planning → fresh Readiness → fresh Execution → fresh Verification` 重开；需要修改合同或用户保留决定时，先取得用户确认。新实现只能依据重新核对的合同与当前 main 独立产生。
- 新主会话成功建立且清理结果已向用户说明后，旧主会话结束并归档，不再设计、实现、验证或继续协调新尝试。平台保留的旧会话不改变这一终态。
