# Vorton 设计哲学

> 2026-09-29 重新锚定；2026-10-02 按新的状态模型改写公理 3、4，并同步到 `lang-spec/`。`design.md` 与实现尚未同步；冲突时以本文件为准。

Vorton 是一门给 LLM 写、给人定边界的 native 语言。代码主要由 agent 大量产出，正确性由编译器保证，人只掌握模块、接口与能力这一层。人是项目的目的，也是最大的瓶颈。

需求边界以“用 Vorton 重写一个 Godot 级游戏引擎”为准：性能、表达力、FFI、渲染、插件 ABI 都要，裸机不在范围内。本文件只保存用于仲裁设计取舍的公理；可观察规则以 [`lang-spec/`](lang-spec/README.md) 为准。

## 三方分工

- **人**在宏观上 steer：定方向、定边界、批准宏观变化。
- **agent** 在微观上 maintain：写实现、修错误、跟随编译器。
- **编译器**是机械 leader：看见整个仓库，判定一切可机械判定的事，把其余压缩成少数可读的点交给人。

人的意图以自然语言到达 agent，无法机械检查。因此它造成的任何宏观后果，都必须落到编译器可检查的那一层：地图、能力、依赖、签名、测试。

## 公理

### 1. 编译器是仓库的机械 leader

- 视野是整个仓库。仓库内的 Vorton 代码对编译器全程序可见；只有 C ABI/FFI、`unsafe` 与插件 ABI 是需要显式声明的外部边界。
- 向下，给 agent 快速、局部、精确的反馈；向上，给人仓库地图、模块卡片与变更报告。
- 必须可预测：规则少而硬，相同输入得到相同结论。编译器必须终止；编译速度是 leader 的职责，增量编译是一等需求。
- 类型推断采用局部双向推断：函数签名写出，函数体内推断。能力与访问由编译器在全仓库范围推断。

### 2. 人的注意力是最稀缺的资源

- 需要人批准的只有宏观变化：新增顶层模块、新增依赖边、放宽能力上限、公开签名变化、规模异常。
- 模块内部的任何东西都不上报，没有例外。
- 仓库地图与模块卡片由编译器生成并提交进仓库，因此不会过时，变化会出现在 diff 里。
- 每个批准点都必须是人几秒内能真正判断的事。宁可少报，也不能让人养成盖章的习惯。
- 批准权可以按顶层模块分派给其他人或受信任的 agent。

### 3. 能力由编译器推断，effect 是注入

- **能力**是函数可能碰到什么：文件、进程、控制台、`unsafe`、会修改哪些实体。能力由编译器在全仓库范围推断，不写进函数类型。
- 模块的能力上限由人设定，由编译器强制执行。这是人约束 agent 的主要杠杆：约束“能做什么”，而不是“怎么写”。存进数据的回调，能力算在定义它的模块。
- **effect** 是注入：用户定义的 effect 与 `handle…with`、`fail` 与 `catch`，由调用方的上下文提供实现，让依赖替换与测试变得廉价。调用方需要知道自己要处理什么，因此 effect 是函数类型的一部分。
- effect 在函数签名中的具体写法尚未定稿。

### 4. 值、实体与访问

- **值**没有身份：数字、`Bool`、不可变的 `Str`、`Handle<T>`，以及只由值组成的 struct、tuple 与 enum。赋值就是拷贝，与 C++ 的值类型相同。
- **实体**有身份：容器、实现 `Drop` 的类型，以及含有它们的类型。实体不会被隐式复制：不加标记的赋值、传参与返回都是移交，需要副本时显式 `clone`。实体的所有者是变量、另一个实体或 Region；所有者结束时，实体确定地释放。
- 临时借出用 `&`（只读）与 `&mut`（可改），写法与 Rust 同形，参数、调用处、receiver、返回值、绑定、循环与匹配都一样。借出不复制，只在作用域内有效，不能存进字段、容器或泛型参数；返回的借出只能来自参数。
- 跨调用指称一个实体用 `Handle<T>`。句柄只说明“哪一个”，不让对方存活，也不带访问权；它只由显式创建的 Region 发放。经句柄访问时，函数必须持有该 Region，持有关系写在签名里，归属在运行时检查。对方已经不在时，访问失败，绝不会访问到别的实体。
- 共同所有用库类型 `Shared<T>`，共享状态的修改经由 `Cell<T>`。编译器判定哪些类型可能成环，只对这些类型做运行时环回收。没有全局 GC。
- 一条总规则：**别名与修改互斥**。冲突按实际位置判定：编译期能证明的在编译期检查，证明不了的在运行时检查。读取值是当场拷贝，不构成冲突。不引入生命周期标注。
- 修改调用方持有的数据只有两条路：签名中标明的 `&mut` 参数，以及 `Cell`。两者都对编译器可见，因此修改不需要作为 effect 追踪。
- native、无强制托管 runtime，经 C11 生成程序。裸指针、`unsafe` 与 FFI 是模块能力，会出现在仓库地图上。

### 5. 隐藏语义，公开代价

- 代价模型写进规范，并且保持很小：只有少数几条保证，例如尾调用不增长栈、实体在所有者结束时释放，不读编译器也能推断。其余优化一律尽力而为，不可依赖。
- 编译器导出每一处代价决定（复制、分配、引用计数、运行时检查），分层提供给 agent，不一次倾倒。
- 性能意图用断言表达：做不到就是编译错误，并指出原因。编译器永远不静默降级一个被断言过的期望。
- 需要完全掌控时，把代码放进持有 `unsafe` 能力的模块（飞地），那里一切显式。
- 飞地只能向下集中，不能向上扩散。一个模式离开飞地，只能成为有规范的库抽象或代价保证，不能因为优化器“通常能处理”就离开。应用层飞地应随成熟度趋近于零；基础层飞地集中在少数位置，并接受最严格的审查。

### 6. 每一种自由都有成本，默认不给

- 每个语言特性、每项编译器保证、每次飞地扩张，都要说明服务哪个真实场景（以 Godot 为准），以及给 agent 增加了哪些新选择。
- 一种事只有一种写法。自由度是坏品味的栖息地。
- 规范维护一张“不做清单”并写明理由；恢复其中任何一项，都属于宏观决定。
- 语言设计本身同样受注意力约束：同一时间只开少数几个设计问题。

## 偏好

- 借用熟悉的写法；与其它语言同形的写法必须同义。
- 过程式与函数式结合，不引入 class 或继承；数据抽象由 `struct`、`enum`、`trait` 构成。
- `Option<T>` 是数据，`fail<E>` 是 effect；panic 不可恢复，也不 unwind。
- 命名用 `snake_case`，注释只有 `//` 行注释。
