# Vorton 语言规范

本规范是 Vorton 编程语言的权威参考，独立于任何具体编译器实现。字符到 token 只以[词法结构](lexical.md)为准，token 到语法结构只以[语法](syntax.md)中的 EBNF 为准；其余页面只解释语义，不复制产生式。设计取舍的仲裁依据见[设计哲学](../philosophy.md)。

## 记号约定

- `monospace` 表示关键字、标识符或代码片段
- EBNF 使用 `::=` 定义产生式，`|` 表示选择，`?` 表示可选，`*` 表示零或多个，`+` 表示一或多个
- 类型规则使用标准推导记法：前提在横线上方，结论在下方
- `Γ` 表示类型环境，`⊢` 表示类型判断
- `τ`、`σ` 表示类型；`ε` 表示 effect row；`α`、`β` 表示类型变量

## 不做清单

以下事项有意不做。恢复其中任何一项都属于宏观决定，由用户批准。

| 不做 | 理由 |
|---|---|
| 把格式错误降级为警告的开关 | 同一份代码在任何项目里都应得到相同结论，也不应分裂出两种写法；需要时由格式化工具自动修正 |
| 生命周期标注与借用检查 | `&` 与 `&mut` 不能存下来，借出持续到最后一次使用，静态检查不需要标注；需要跨调用指称的访问一律走运行时检查（`Handle<T>`、`Cell`） |
| 隐式的作用域 Region | 句柄只由显式 Region 发放；局部变量拥有的实体用 `&`、`&mut` 借出 |
| 全局 GC | 回收只出现在 Region 的可选策略与可能成环的共享类型上 |
| 闭包按引用捕获 | 共享的可变状态写成显式的 `Shared<Cell<T>>` |
| 由程序员挑选的多种共享与内部可变类型（Rc/Arc、Cell/RefCell/Mutex 之分） | 编译器知道值是否跨线程，只提供 `Shared<T>` 与 `Cell<T>` 各一种 |
| class 与继承 | 数据抽象由 `struct`、`enum`、`trait` 构成 |
| 外部契约 | 接口由编译器生成，人批准接口变化 |
| `const fn` 与编译期代码生成 | 代码生成由构建期程序完成，编译器保持必定终止 |

## 范围

本规范描述 0.1 的目标语言；各项规则在对应 Milestone 中实现，尚未实现的规则仍是实现的目标。尚未定稿的事项在各页标注“待定”。Compiler 架构见 [`../design.md`](../design.md)。语言内建类型 `Str`、`List`、`Map`、`Set` 的方法在[类型系统](type-system.md)中定义；标准库的模块、类型、函数与方法不在语言规范中定义；示例中未由本规范赋予语义的函数或方法名只用于展示语法与类型关系，不构成库 API。
