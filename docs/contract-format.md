# Vorton contract format 1

`vorton_compiler::decode_contract(&[u8])` reads one in-memory contract document and returns an owned, opaque `ContractDocument`. Successful decoding means that the bytes satisfy the supported UTF-8 JSON profile, version fields, and complete record structure. It does not bind an owner or reference to a source library, apply `set`, run `check`, validate declaration or formal existence, or establish an effective signature.

The complete structural definition is [`contract-format-1.schema.json`](contract-format-1.schema.json). A document has `format: "vorton.contract"`, `format_version: 1`, `semantics_version: "0.1"`, a non-empty host-selected `owner` label, an ordered `records` array, and optional display text. Records preserve every selected `set` and `check` clause, target and formal reference, parameter position, type parameter name, array order, and the distinction between an omitted optional field and an explicit empty array.

The decoder applies these additional wire rules that JSON Schema alone does not express:

- Every object rejects duplicate members after JSON string escapes are decoded, as well as unknown members and tags. Explicit `null` is not valid for any optional field.
- Indices, `type_parameter_count`, and `format_version` use the full `u64` range and require unsigned decimal JSON integer tokens. Negative signs, fractional syntax, exponent syntax, and values beyond `18446744073709551615` are rejected.
- The root container has depth 1. Container depth through 127 is supported; reaching depth 128 is rejected by the fixed reader profile. Brackets inside strings do not affect depth.
- Exactly one JSON document plus trailing JSON whitespace is accepted. Comments, a second document, invalid UTF-8, and other relaxed JSON forms are rejected.

`ContractDiagnostic` reports a stable `ContractDiagnosticKind`, readable message, and the nearest JSON path and input position that the decoder can prove. Position fields are optional because version and cross-field structure checks do not always retain a parser location. Contract diagnostics do not contain Vorton `LibraryId`, `SourceRef`, or a fabricated source origin; the caller owns the association between an error and the supplied byte document.

## Current Checker consumption

`vorton_compiler::check_project` accepts decoded documents together with an explicit `BTreeMap<String, LibraryId>` from each document's owner label to one reachable library in the same `ProjectSources`. `self` and `dependency` references consume that real library identity, its direct dependency aliases, and the Resolver's frozen logical module/namespace bindings. They never use an OS path, numeric-ID convention, global leaf-name search, or a second Resolver pass. A record may target an owner-local ordinary function, including a private one; a dependency's public alias or facade may supply a supported type operand, but a re-export cannot transfer ownership of a foreign function target.

The current Checker subset applies `set.parameter_types`, `set.return_type`, fixed Borrow/Move `set.parameter_modes`, explicit empty `set.effect_upper`, and explicit empty `set.generic_requirements`. Types are limited to `Int`, `Float`, `Bool`, `Unit`, `Never`, tuples of those types or declaration type formals, and references to usable non-generic transparent aliases. Omitted clauses remain omitted, including the distinction between an omitted `generic_requirements` and explicit `[]`. Partial records for the same exact target merge idempotent normalized values and reject conflicts rather than using document order as last-wins.

For a generic function, the grouped records must provide an explicit `type_parameters` list with the same arity as source and must state every parameter type plus the return type. Formal references bind by exact target, declaration binder, type kind, and ordinal; `type_parameters` spellings are display names and may differ by alpha-renaming. A formal from another owner, a merged or split relation, or a concrete type that specializes the source relation is a conflict. A fragment that omits `type_parameters` contributes no binder declaration; another fragment for the same target may supply the complete alpha-equivalent list.

All other target/type/mode forms, non-empty effect or requirement rows, `parameter_escape`, and every `check` clause produce `CheckDiagnosticKind::Unsupported`. If one record selects both supported and unsupported clauses, the entire record is rejected before any supported fact can affect checking. Binding failures and conflicting selected facts use their own stable diagnostic categories. These diagnostics identify the actual document index and JSON path and may relate a real source `OriginRef`; they do not invent contract byte positions, source spans, or libraries.
