# Vorton contract format 1

`vorton_compiler::decode_contract(&[u8])` reads one in-memory contract document and returns an owned, opaque `ContractDocument`. Successful decoding means that the bytes satisfy the supported UTF-8 JSON profile, version fields, and complete record structure. It does not bind an owner or reference to a source library, apply `set`, run `check`, validate declaration or formal existence, or establish an effective signature.

The complete structural definition is [`contract-format-1.schema.json`](contract-format-1.schema.json). A document has `format: "vorton.contract"`, `format_version: 1`, `semantics_version: "0.1"`, a non-empty host-selected `owner` label, an ordered `records` array, and optional display text. Records preserve every selected `set` and `check` clause, target and formal reference, parameter position, type parameter name, array order, and the distinction between an omitted optional field and an explicit empty array.

The decoder applies these additional wire rules that JSON Schema alone does not express:

- Every object rejects duplicate members after JSON string escapes are decoded, as well as unknown members and tags. Explicit `null` is not valid for any optional field.
- Indices, `type_parameter_count`, and `format_version` use the full `u64` range and require unsigned decimal JSON integer tokens. Negative signs, fractional syntax, exponent syntax, and values beyond `18446744073709551615` are rejected.
- The root container has depth 1. Container depth through 127 is supported; reaching depth 128 is rejected by the fixed reader profile. Brackets inside strings do not affect depth.
- Exactly one JSON document plus trailing JSON whitespace is accepted. Comments, a second document, invalid UTF-8, and other relaxed JSON forms are rejected.

`ContractDiagnostic` reports a stable `ContractDiagnosticKind`, readable message, and the nearest JSON path and input position that the decoder can prove. Position fields are optional because version and cross-field structure checks do not always retain a parser location. Contract diagnostics do not contain Vorton `LibraryId`, `SourceRef`, or a fabricated source origin; the caller owns the association between an error and the supplied byte document.

## Current Checker consumption

`vorton_compiler::check_project` accepts decoded documents and an explicit `BTreeMap<String, LibraryId>` from each document owner label to a reachable source library. References use that library's direct dependency aliases and the Resolver's frozen bindings. Records can select owner-local ordinary functions, trait methods and impl methods, including private callables; re-exporting a foreign callable does not transfer contract ownership.

The Checker applies parameter/return types, fixed Borrow/Move modes, shared-Fn `callable_use`, generic requirements, and effect upper bounds. Supported types include scalar primitives, tuples, struct/enum applications, non-generic transparent aliases, exact type formals, owner `Self`, and legal associated projections. Receiver has its own selector; positional arguments exclude it. Trait/impl owner formals and method formals bind separately by exact owner, binder kind and ordinal. `ImplRef` matches library, type-parameter arity and normalized target/trait patterns; multiple matches are an error even when different where clauses make the impl domains disjoint. Source spans and where text are not public identity fields.

Partial records are grouped before input-domain and body constraints. Requirements preserve three states: omitted, explicit `[]`, or P. Selected P is retained rather than inferred from an actual caller or narrowed by an unused body; outer formation conditions remain mandatory. A selected domain is available to source associated-type lookup, and selected receiver types are available to method/field constraints. A generic source callable and its grouped records explicitly declare the same own type-parameter arity. Alpha names may differ, but owner/ordinal and parameter/result relationships must agree; a contract cannot specialize an unconstrained source identity to a concrete type.

Rows consume system, handled, fail, mut, unsafe, effect formal, method application, full destruction and shared-Fn selected-call terms. Method type/effect actuals and owner arity are checked. An omitted shape row keeps the selected callback relationship; pure and non-empty actual callbacks are checked by the same minimum-actual solver. Public upper bounds are checked and preserved, including inherited trait bounds. Conflicting partial clauses are not unioned. Explicit source/contract type differences are errors; differing explicit properties without an established difference policy remain Unsupported.

Other record targets, unsupported type/resource capabilities, `parameter_escape`, and all `check` clauses remain Unsupported. Handler/catch, capturing closures, general callable storage/returns, FnMut/FnOnce entry, user Drop/Rc/Weak and Mut/partial-move semantics are not enabled by a decoded record. A mixed record is rejected atomically if any selected clause is unsupported. Diagnostics retain real document indices/JSON paths and related source origins; successful decoding alone never establishes a semantic contract.
